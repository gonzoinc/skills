# Local Tracker Conventions

Reuse the project's established notes and ticket location. Agree a location before creating a new directory. Keep one self-contained file per implementation ticket, numbered in dependency order if that matches the project, with title, delivered behavior, acceptance criteria, blockers and status. Reuse existing status names; no label setup is required.

Specs and ticket comments use existing formats. “Publish” means write to the approved local location; external publication requires its own authorization. Fetch a local ticket by reading its referenced file.

`project-planner` maintains its decision map in existing project notes, with decision name, type, status, blockers and resolution. A frontier decision has no unresolved blockers and is unclaimed. Claim locally before work; on resolution record the answer and link it from the decision index. Reuse anchors in a single file when appropriate.
